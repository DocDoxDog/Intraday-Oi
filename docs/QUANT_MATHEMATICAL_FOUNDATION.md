# Quant Mathematical Foundation\n\n## Purpose\nAdd a mathematical research layer to Intraday-Oi without turning formulas into autonomous trading decisions.\n\nSOURCE → OBSERVED FACTS → MATHEMATICAL MODEL → MODEL OUTPUT → EVIDENCE RELATIONSHIPS → REASONING → VERIFICATION → NARRATIVE\n\n## Domains\n- Linear algebra: covariance/correlation, PCA, factor structure, stable matrix operations, surface representation.\n- Calculus: Greeks, first/second-order sensitivities, curvature, local response.\n- Probability: conditional distributions, expected payoff, tail probabilities, uncertainty and calibration diagnostics.\n- Stochastic processes: Brownian motion, GBM, mean reversion, stochastic volatility, regime switching.\n- Stochastic calculus: Ito, SDEs, quadratic variation, martingales, Girsanov, Feynman-Kac.\n- Pricing: Black-Scholes-Merton, Bachelier, CRR/binomial, Monte Carlo, PDE/finite difference.\n- Volatility: IV, realized volatility, term structure, skew/smile, surface interpolation, SVI research.\n- Numerical methods: IV root finding, interpolation, integration, finite differences, Monte Carlo convergence, calibration.\n\n## Financial semantics\n- OI is positioning, not traded volume.\n- ΔOI is not aggressor direction.\n- GEX is context, not a directional oracle.\n- level ≠ trigger; trigger ≠ confirmation.\n- model probability ≠ market fact.\n- implied volatility ≠ realized volatility.\n- pricing-model output ≠ observed price.\n- missing evidence remains missing.\n- OI, GEX, Max Pain, Pinning, walls, gamma flip, IV/skew and model-derived distributions are a connected structure, not independent votes.\n\n## Architecture\nResearch reference modules should live under research/quant/: linear_algebra, calculus, probability, stochastic, pricing, greeks, volatility, numerical, calibration.\n\nProduction may consume a model only through a typed contract:\n\nQuantModelResult:\n- model_id\n- model_version\n- as_of\n- input_refs\n- assumption_refs\n- output\n- uncertainty\n- diagnostics\n- calibration_status\n\nOutput types must distinguish scalar, vector, surface, distribution and scenario set.\n\n## Validation tiers\nTier 0: mathematical identities, limiting cases, symmetry/monotonicity where applicable.\nTier 1: numerical benchmarks, convergence, tolerance, finite-value and conditioning checks.\nTier 2: point-in-time market inputs, provenance, stale/missing detection, cross-source reconciliation.\nTier 3: OOS, purged/embargoed evaluation where applicable, calibration and transaction-cost awareness.\nTier 4: deterministic regression, evidence-reference preservation, provenance, fail-safe behavior, no execution authority.\n\n## Implementation order\n1. Numerical primitives\n2. Black-Scholes/Bachelier + Greeks\n3. IV solver\n4. Realized-vs-implied volatility\n5. Volatility surface\n6. Distribution/tail research\n7. Stochastic simulation\n8. Calibration\n9. Evidence-ledger integration\n10. Reasoning integration\n\nDo not begin with a predictive trading model.\n\n## Reference repositories\nUse GitHub quant projects as audited references, not runtime dependencies. Candidate families include Quant-Projects, quant-finance-pricing-lab, quant-finance-practice-and-theory, derivatives-analytics-py and formal-mathfin. Review license, implementation quality and point-in-time assumptions before reuse.\n\n## Non-goals\nNo autonomous trading, no direct BUY/SELL generation, no replacement of deterministic OI/GEX calculations, no hidden model blending, no fabricated probabilities, and no treating model output as observed market fact.
